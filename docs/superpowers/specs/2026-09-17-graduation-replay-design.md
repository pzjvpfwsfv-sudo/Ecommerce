# G2-A 可恢复历史回放设计

日期：2026-09-17。用户已确认固定速率、暂停恢复、真实字段不变、独立 Topic 与至少一次发送边界；按此范围实施，不扩展为调度平台。

## 1. 输入与输出

读取 G1 标准化 JSONL 及同名 `.provenance.json`，核验数据集、文件大小、SHA-256、跨月来源、无逆序及无已选拒绝记录。所有读取有界，不将百万行装入内存。每条发送前重算标准化身份，拒绝缺字段、未知字段、重复 JSON 键、非法值及不匹配的事件 ID。

新增入口 `python -m generators.real_data.replay`，与旧模拟发送器隔离。默认 `--mode dry-run`，显式 `--mode kafka` 才发送；每次默认处理 1,000 条，`--rate 100` 表示每秒最多约 100 条，不追赶积压造成突发。

真实业务字段、历史 `event_time` 和稳定 `event_id` 不变。消息另加 `replay_id`、`replayed_at`、`replay_schema_version`。Kafka key 使用数据集及用户身份，使同一用户在分区数不变时保持同分区；不宣称跨分区全局有序。

## 2. 断点与恢复

本地 JSON 断点保存任务 ID、输入 SHA/大小/行数/数据集、运行模式、bootstrap 地址、Topic、已确认记录数及最后事件 ID。恢复重新校验源文件，逐行跳过已确认前缀并核对最后事件身份；不实现复杂的外部索引。

断点通过同目录临时文件、flush/fsync 和原子替换写入，每 100 条确认保存一次；正常限量结束及 Ctrl+C 时保存已确认前缀。不能把异步 send 入队当作确认。发送失败不前移未确认进度；强制终止可能重复本批已发送事件，依靠后续稳定 ID 去重，不宣称端到端 exactly-once。

单任务采用操作系统文件锁，进程结束自动释放，避免陈旧 PID 锁。锁文件保留，不人工删除正在运行的锁文件。不同断点文件代表不同任务；程序不提供跨任务去重。dry-run 与 kafka 断点不能互用。输入、清单和断点不能使用同一路径。

恢复保证以目标 Kafka 日志仍存在为前提。此版绑定连接地址和 Topic 名，不检测集群日志丢失、保留期清理或同名 Topic 重建；发生这些情况须重新建立回放任务并对账，不能沿用旧断点当作成功。

## 3. Kafka 与范围

复用已锁定 `kafka-python==2.1.2`，新建独立适配器，保留旧发送器行为。使用 `acks=all`、有限重试、单连接单在途请求、有限缓冲及发送等待超时；等待 send 返回的 future 确认后才推进计数。参考 [KafkaProducer 2.1.2 文档](https://kafka-python.readthedocs.io/en/2.1.2/apidoc/KafkaProducer.html)。

只允许 `real_behavior_events_v1` 或其带后缀的验证 Topic，禁止写旧 `user_behavior_*` Topic。关闭自动建 Topic，目标必须显式创建。默认仅本地明文开发连接；不将本次适配器当生产鉴权方案。副本因子为 1 时 `acks=all` 不等于多副本容灾。

本轮不改 Java Flink 作业、现有 Topic/表、Docker 卷、业务页面或 RAG；不批量发送全部 220 万条。

## 4. 验收

- 人工边界夹具只用于测试：恢复不跳过未确认事件、正常暂停保存前缀、故障允许重发但不换业务 ID、文件/目标/模式不一致拒绝、锁并发拒绝、坏断点及超长记录拒绝、旧字段不被改写。
- 真实样本离线试跑先处理 400 条，再恢复 600 条，核对总计 1,000 条和原文件身份。dry-run 不连接 Kafka，不称作 Kafka 验收。
- Kafka 可用时显式创建唯一验证 Topic，用真实样本执行相同 400+600 条回放；独立消费者按任务 ID 核对 1,000 条、事件 ID、业务内容与 key，不只看 producer 成功日志。
- Docker 不可用时记录环境阻塞，不为了通过验证重置旧服务；保留代码/离线验证与动态验收的区别。
