# 毕设与校招版系统设计

日期：2026-09-17。状态：依据本次对话已确认的范围执行；本文件不代表所有功能已实现。

## 1. 定位与范围

课题：**基于实时湖仓与检索增强智能体的电商行为分析系统设计与实现**。

方向：数据工程与大模型应用相结合的系统开发。用户是运营人员、分析人员和管理员，不建设购物商城，不研究模型训练算法。

首月目标是可演示、可解释、可验证的核心系统。9 月底形成数据选型依据、首批文献和开题架构；约四周形成面试核心版。排期须在首阶段真实数据验收后校准，不是完成时间保证。

## 2. 当前基础与缺口

- 复用现有 Kafka KRaft、Java Flink DataStream、Doris、Iceberg/MinIO、Trino、FastAPI 和受控工具调用。
- 开发继续使用 `.worktrees/chapter-10-controlled-tools`；不覆盖主目录已有修改。
- 旧事件包含模拟渠道、设备、页面字段，不能伪造这些字段来兼容真实数据。真实事件使用独立版本，后续独立 Topic 和表，完成对账再接入新页面。
- 第 10.5 章完整动态验收尚未通过；新增离线测试通过不能替代既有链路的动态验收。
- 完整业务前端、真实数据指标、知识库、RAG 和评测仍需开发。

## 3. 数据与真实性边界

主候选为 REES46 多品类行为数据。来源：

- https://rees46.com/en/datasets
- https://data.rees46.com/
- https://www.kaggle.com/datasets/mkechinov/ecommerce-behavior-data-from-multi-category-store/data

发布方说明包含真实匿名化业务事件。真实性陈述依据发布方，不声称审计过企业原库。下载时保留来源、文件身份、SHA-256、获取时间、使用说明和采样方式；原始文件不提交 Git。

系统使用真实历史记录进行可控流式回放，不宣称实时连接企业生产接口。原始事件时间、接入时间和回放时间分离。回放历史基线与增量区间不得重复累计。

原始字段：`event_time,event_type,product_id,category_id,category_code,brand,price,user_id,user_session`。

- 保留用户、商品、品类 ID 为字符串，避免大整数精度损失。
- 保留缺失会话、品牌和品类为 null；不生成替代业务身份。
- 价格采用十进制定点字符串；购买事件价格合计不是净收入、利润或经财务确认的 GMV。
- 允许 view、cart、remove_from_cart、purchase，不把未知事件偷偷映射成浏览。
- 技术事件 ID 由数据集身份、源文件身份、原始记录序号和标准化内容确定；重试稳定，不把内容完全相同但序号不同的合法事件自动删除。
- 不同来源隔离用户和商品身份，不拼造跨平台转化路径。
- 单元测试可以使用明确标注的人工边界样例；业务演示和性能数据必须标注真实来源，不把测试夹具冒充业务数据。

首阶段前缀样本仅验证解析、质量和吞吐，不验证留存或完整用户路径。正式分析优先覆盖至少两个月；如缩小规模，按稳定用户采样保留窗口内完整行为，记录样本范围。不能用重复事件凑百万行。

## 4. 功能与指标映射

| 页面/模块 | 真实字段与业务问题 | 验收边界 |
| --- | --- | --- |
| 数据接入 | 来源、版本、文件、回放任务、进度、暂停和续传 | 稳定事件 ID，确认发送后记录进度；重试不重复累计 |
| 运营总览 | 事件时间、类型、用户、价格；发现流量和购买变化 | 指标带口径、业务日期、数据更新时间，不把历史日期改成今天 |
| 转化分析 | user_session、event_time、event_type；定位流失阶段 | 相同会话内按时间排序；完整观察窗口；缺失会话单列，不直接用事件数相除 |
| 商品/品类分析 | 商品、品类、品牌；高浏览低购买与结构变化 | 显示有效样本量；未知维度保留；支持指标到明细下钻 |
| 用户分析 | user_id、event_time；活跃、首次观测分组、回访和留存 | 首次观测不等于真实注册；留存剔除观察期不足的分组 |
| 数据质量 | 缺失、非法、迟到、重复处理、湖仓对账 | 区分源数据问题与处理故障；可追溯异常样本 |
| 知识库 | 文档上传、预览、分类、分块、版本、发布和删除 | 更新后检索新版，删除后旧版本不能命中 |
| 智能分析 | 检索口径、调用指标工具、图表、解释、保存报告 | 同时有文档出处和数据证据；无依据拒答；相关性不冒充因果 |
| 基础管理 | 管理员、分析员、只读用户，执行和操作记录 | 后端鉴权；知识权限在检索前过滤，不依赖前端隐藏 |

不纳入首月：库存、物流、退款、利润、虚构人口画像、多 Agent、任意 SQL、模型微调、知识图谱、扫描件 OCR、Kubernetes。既有 KRaft 架构演进实验保留，不为演示增加常驻集群规模。

## 5. 架构职责

`真实源文件 -> 标准化/可控回放 -> Kafka -> Java Flink -> Iceberg 明细 + Doris 指标 -> FastAPI -> 业务界面`

`真实文档/口径 -> 解析分块 -> PostgreSQL + pgvector -> 检索工具 -> 现有受控 Agent -> 图表与引用`

- Iceberg 保存可审计事实与重算依据，Doris 服务高频指标，Trino 查询历史明细。独立 sink 不声称全局 exactly-once，使用稳定标识、口径版本和对账保证结果可解释。
- 复用 FastAPI，不另建一套 Java 业务后端。Java 保留在 Flink 数据计算层。
- 前端采用 React + TypeScript + ECharts，统一筛选器和布局，先完成 6～8 个核心页面，不做只播放预计算结果的展示壳。
- PostgreSQL 业务/知识数据库与 Hive Metastore 分库、分角色。pgvector 是否可用须通过镜像和扩展验收，不默认旧镜像已有扩展。
- 16 GB 本机按运行模式限制服务资源；不常驻本地大模型。Trino 按需启动，有依赖的元数据服务不能任意停用。

## 6. RAG 与 Agent 核心交付

知识来源为数据字典、版本化指标定义、标明来源的分析规则、项目操作手册和真实排障记录。自行编写规则明确标记，不冒充企业资料。海量行为流水不逐条向量化。

首版接受 Markdown、TXT 和带文本层 PDF；不支持的格式明确拒绝。保存文档 ID、版本、权限、标题、章节或页码、块 ID、内容摘要与索引状态。构建新版成功后再发布，失败不损坏现有版本。删除覆盖内容、块、向量和检索可见性。

先做关键词和向量两路检索、排名融合；中文检索需要明确分词策略，不把 PostgreSQL 默认全文检索误称为中文 BM25。重排序由独立评测决定，不强制增加组件。

复用现有工具白名单、统一 deadline、审计和降级，新增知识检索与版本化指标工具。文档作为不可信证据，不能执行其中的指令。禁止文档触发额外权限、写入或任意外部调用。引用返回可定位的原文片段，不展示模型隐藏思维链。

验收问题示例：“上一完整时段手机品类转化下降集中在哪些商品？转化率如何计算？”需要调用知识与数据工具，程序计算差异，返回图表、口径版本、查询范围和引用。

建立至少 50 条独立人工校验问题，覆盖知识问答、指标查询、混合分析、无答案、过期文档、越权和提示注入。对比关键词/向量/混合检索，记录 Recall@k、引用正确性、任务成功率、拒答表现、耗时和调用成本。测试集不用于反复调参，模型裁判结果需抽样人工核验。

## 7. 实施阶段

| 阶段 | 可验证交付 | 前置条件 |
| --- | --- | --- |
| G1 数据依据 | 源登记、流式标准化、质量画像、真实样本验证、完整窗口选型 | 不依赖 Docker；当前开始实施 |
| G2 真实链路 | 可恢复回放、独立 Topic/表、DataStream 适配、指标和对账 | G1 字段和窗口验收；修复旧动态验收阻塞 |
| G3 业务界面 | 统一筛选、总览、商品/品类、漏斗、数据质量 | 已验证的指标 API；基础权限 |
| G4 知识与智能 | 知识库完整生命周期、混合检索、受控 Agent、引用、报告 | 与 G3 共用认证、指标版本和页面规范 |
| G5 答辩证据 | 百万级处理、故障恢复、RAG 对比、演示脚本和简历描述 | 用真实测量填写结果，不预设吞吐与准确率 |

G1 工具测试通过不等于真实数据链路或毕设完成。进度和未完成项必须分别记录。
