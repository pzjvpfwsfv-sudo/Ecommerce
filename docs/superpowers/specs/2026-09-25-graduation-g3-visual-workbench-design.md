# G3 真实数据可视化工作台设计

日期：2026-09-25
状态：视觉方向已确认，本文待用户审阅；不是实现完成声明。

## 1. 目标与设计原则

G3 面向答辩演示和日常分析，提供能操作、能解释、能追溯的业务工作台，而不是静态大屏。用户已确认协调后的绿色方案：深绿导航、暖白内容区、克制的灰绿层次和少量强调色；保留科技感，但避免深绿与荧光浅绿直接冲突。

统一的是产品骨架、筛选规则、指标证据和交互反馈，不是把所有页面套进同一套 KPI 卡片加折线图。每个模块先确定业务问题、数据粒度和可用字段，再选择图形、布局和下钻方式。图表必须帮助读者作判断，不能只为“高级感”增加 3D、装饰性动画或无意义切换。

本阶段沿用已确认的 React + TypeScript + Vite + ECharts、FastAPI 和独立 PostgreSQL 业务库。业务库与现有 Hive Metastore 分离；G4 再在该业务库验证并启用 pgvector。前端与 API 使用同源访问，权限由后端执行，不以隐藏按钮代替鉴权。

## 2. 数据边界

- Olist 订单域读取已发布的 `orders-v1` 指标与来源证据；订单是匿名化历史快照，不显示“正在发生的实时订单”或虚构的当日增长。
- REES46 行为域读取已发布的 `behavior-v1` 指标；当前公开验收为 1,002 条真实事件的正确性子集。界面必须展示 `data_scope` 与警告，不把它说成完整的 2% 样本或百万级生产结果。
- 两个来源各有独立的身份、时间范围、指标版本和发布运行。总览可以并列呈现两域状态，但不合并订单数、用户数、金额，也不画跨源转化路径。
- 购买事件价格合计标为“购买金额代理值”，不得标为销售额或 GMV；Olist 商品值、运费值、支付值不得标为利润、净收入或审计 GMV。`source_currency` 为空时不显示货币符号。
- 页面显示业务时间窗口、计算时间、发布时间、数据集、版本和 run ID。筛选只使用 API 真正支持的粒度：行为域 `day/full`；订单域 `day/month/full`，且 `full` 不传日期范围。
- 不在前端补造缺失维度、伪造平滑趋势、以 0 代替 null，或把 Top N 排名说成全体分布。缺少资格样本时显示“不适用”和分子、分母。

## 3. 信息架构与模块差异

共享工作台外壳负责侧栏、面包屑、账户、响应式布局与统一状态反馈。模块内容按下表独立设计；下表的可交互内容只使用现有聚合 API，不承诺尚无 API 支持的逐单明细下钻。

| 模块 | 核心问题与展示形态 | 首版有效交互与数据来源 |
| --- | --- | --- |
| 运营总览 | 订单指标、历史趋势与发布状态组成“决策摘要”，行为域状态另列，不做跨源总计；趋势用按日或月的时间序列，而非每项都做卡片 | 切换订单粒度和合法日期范围、悬停查看确切值与窗口、打开指标证据；`orders/overview`、两域 `publication` |
| 行为与转化 | 会话阶段用有序阶梯漏斗，明确缺失会话和每一步分母；事件趋势与漏斗分区呈现 | `day/full` 切换、悬停查看阶段人数和比率、点击阶段高亮对应定义；`behavior/overview`、`behavior/funnel`、`behavior/quality` |
| 订单与支付 | 订单状态比率和订单量用组合趋势；支付方式用可比较的横向条形图，不用难读的多层环图 | 时间粒度切换、支付方式排序、订单数与支付值切换、查看已有比率的分子分母；`orders/overview`、`orders/payments` |
| 商品与品类 | 排名比较用横向条形图和紧凑数据表；商品、品类、卖家、地域维度各自显示适用指标，不把不同粒度金额混算 | 维度与合法排序切换、Top N 选择、行选中后显示该行聚合证据；`orders/rankings`、`behavior/rankings` 分域展示 |
| 履约与评价 | 履约用平均值、P50/P90 和晚到率的时间视图；评价用评分均值、覆盖率、低分率的并排趋势，二者不假装存在评分分布明细 | 切换履约/评价视角、悬停查看合格与排除订单数、时间范围联动；`orders/delivery`、`orders/reviews` |
| 数据质量 | 来源、规范化、入湖、发布组成审计流程图；异常类别用矩阵/列表突出“非零但可报告”与“硬门禁失败”的区别 | 订单/行为域切换、展开行数对账、异常口径和 Snapshot/run 证据；两域 `quality`、`publication` |

G3 同时提供登录与账户页。AI 指标分析、知识库和报告为 G4 的真实功能，G3 不提供伪造聊天、假引用或假报告；如果导航提前露出，必须明确标注“G4 待开放”且不伪装成可用功能。回放任务控制和逐笔明细查询不属于本阶段。

## 4. 视觉与交互规范

- 以已确认的绿色预览为方向：深绿只用于导航和小面积高对比区域，暖白作为主要阅读底色，灰绿作为分隔和状态层，铜色仅作稀疏的对照强调。颜色同时承担语义，不靠颜色单独表达“通过/异常”。
- 预览基准色值为文字 `#1a2e29`、深绿 `#1d3c33`、森林绿 `#2b5b4d`、玉绿 `#2d7566`、浅薄荷 `#e7eee8`、纸张底色 `#f2f2ed`、卡片 `#fdfdfa`、边线 `#d8e0d9`、少量铜色 `#b48361`。实施时允许为对比度微调，但不回到荧光绿或大面积深浅绿硬拼接。
- 共享排版、间距和控件规范，但各页面可使用不同的内容密度、图表比例、空白和辅助手段。图表类型由数据关系决定：时间用线/面积，排名用条形，阶段用漏斗，质量用流程和矩阵；不滥用饼图和地图。地域没有足够地理信息时只做地域排名。
- 图表悬停或键盘聚焦显示名称、精确值、单位、业务窗口及有效样本；点击筛选或切换后标题、图例、数据和证据一起更新，不能只改变视觉外观。
- 打开“数据证据”抽屉可查看数据集、版本、run ID、Snapshot 摘要、发布时间、指标定义和限制声明。抽屉内容必须来自当前响应及定义 API，不沿用预览中的硬编码数据。
- 加载、空结果、无发布、服务不可用、权限不足各有可区分状态和重试路径。筛选变更时保留旧图但标明正在更新，返回后原子替换数据和元信息，避免新旧 run 混屏。
- 桌面端保持清晰的分析层级；窄屏改为可折叠导航和纵向卡片。图表有可读文本/表格替代，键盘可达，焦点可见，动效短且尊重减少动态效果设置。

## 5. 应用边界与权限

前端按 `shell`、`domain-client`、`modules`、`charts`、`evidence` 分离。域客户端解析 FastAPI 响应，保留原始 `meta`，在开发模式对关键字段做契约校验；模块只接收类型化数据，不直接拼接 SQL 或自行重算后端指标。图表组件处理交互和呈现，不拥有指标公式。全局只共享合法筛选状态；订单域和行为域有各自的筛选模型，防止把 `month` 错传给行为域。

新增独立 PostgreSQL 业务库保存用户、角色、会话和必要审计记录，不复用 Metastore 库。首版角色为管理员、分析员、只读用户：三者可阅读获准指标；分析员和管理员可使用受控分析功能；管理员可管理账户和知识发布权限。登录使用安全口令哈希和服务器端会话，浏览器只持有 HttpOnly 会话 cookie；状态修改请求防 CSRF。未登录访问受保护 API 返回 401，权限不足返回 403；现有指标/分析路由必须在后端接入鉴权，不能通过直接访问 FastAPI 绕过。健康检查保留独立、无敏感信息的探活路径。开发代理和生产入口均按同源配置，容器与宿主机端口边界在实现计划中明确。

认证迁移不能悄悄破坏现有测试和脚本：测试使用明确的登录夹具或专用服务身份；真实运行不提供默认免鉴权后门。G4 在同一身份体系上增加知识权限过滤和 pgvector 检索，不在 G3 假实现 RAG。

## 6. 错误处理与验收

API 返回 422 时保留用户当前筛选并解释合法范围；503 时显示“指标暂不可用”而不回退到演示常量。元信息缺失、版本不匹配或两次请求 run 身份不一致时失败关闭，页面不混合显示。数字和比率沿用后端精度，前端只做有说明的格式化；业务统计不在浏览器重复推导。

验收至少覆盖：

1. 六个业务模块各有与问题匹配的独立布局和可操作图表，不是同一模板换标题；桌面和手机宽度均可完整使用。
2. 使用真实已发布 API，完成筛选、图表切换、排序、证据抽屉、错误/空态、键盘操作的组件与端到端测试；不在生产构建中注入演示数值。
3. 对 Olist/REES46 来源隔离、历史时间、子集警告、null、Top N 和金额禁称做页面级检查。
4. 未登录与越权请求在后端被拒绝；登录、会话过期、退出和角色限制有自动化验证。
5. 与现有 API 合同和回归测试一起运行；实际服务不启动时只报告离线测试通过，不宣称动态验收完成。

## 7. 取舍与后续

选择“共享外壳 + 模块专属图表和交互”。相比统一仪表盘模板，开发量略高，但业务问题更清楚；相比每页完全定制，又能复用筛选、证据、错误处理和响应式基础。首版先让真实数据、口径和交互可信，再按 G4 接入知识库/RAG 与有引用的 AI 分析。当前绿色预览是方向稿，不是已接入真实 API 的产品页面。
