# G4 知识库与有据 AI 分析设计

日期：2026-10-08。状态：设计已确认，模型接入策略按用户补充意见细化；这不是功能已实现的声明。2026-10-08 的总路线调整把 [G5-A 全样本行为闭环](2026-10-08-graduation-g5-full-behavior-acceptance-design.md)排在 G4 正式行为分析验收之前；知识库离线开发不受此阻塞。

## 1. 目标与边界

面向毕设答辩和数据开发/AI Agent 面试，交付能管理真实项目资料、检索正确版本、给出可定位引用，并结合已发布指标回答问题的系统。知识库是核心业务模块，不是聊天窗口里的预置答案；Agent 必须由 Python 代码实现模型选择工具、执行、观察和有据回答，而不是拖拽式流程。验收既看可用功能，也看检索评测、工具调用、越权防护和本机资源测量。

沿用 G3 的 React 工作台、FastAPI、会话鉴权和 PostgreSQL 应用库；百万级行为流水仍归 Iceberg/Doris，不逐条向量化。知识库只保存数据字典、`behavior-v1`/`orders-v1` 口径定义、运行手册和有来源的排障记录。项目自行编写的资料明确标为“项目文档”，不冒充企业内部资料。Olist 与 REES46 是独立来源，不做跨源用户关联或虚构因果结论。

不新增 Milvus、Elasticsearch、多 Agent、知识图谱、OCR 或常驻本地模型集群。Milvus 和 Elasticsearch 是检索后端的可选替代品，不是 Agent 成立的前提；本项目继续用 PostgreSQL + pgvector。LangChain 用于**一个实际运行的单 Agent 工具循环**，不是只安装依赖或画流程图。不能因为本机装了模型就跳过检索、引用或评测。

## 2. 组件与运行方式

`真实文档/版本化指标定义 -> 解析与分块 -> PostgreSQL 文档/块/版本 + pgvector 向量 -> 权限过滤后的关键词/向量检索 -> 引用证据`

`用户问题 -> 按需 LangChain 单 Agent（显式选择远程兼容 API 或本地 Ollama）-> 知识检索/已发布指标 -> 模型组织有据回答 -> 后端证据校验 -> 带文档引用和指标 run ID 的回答/报告`

- 应用库使用 PostgreSQL 16 + pgvector，知识表放在独立 `knowledge` schema；原认证表与 Hive Metastore 不改。现有普通 `postgres:16.4-alpine` 镜像**没有经过扩展验收**。启用前检查实际卷和备份；若已有持久数据，不直接用不同基础镜像重挂旧卷，而是先隔离验证迁移。Schema 通过可重复执行的迁移创建，不能只依赖首次初始化脚本。
- 本机已安装 `qwen3:latest`，实测元数据显示 8.2B、Q4_K_M、约 5.2 GB，能力为生成/工具/思考，未列出 embedding。它仅按需做 Agent 工具决策和有据回答，不承担向量化。2026-10-08 的单句冷启动探针耗时 22.07 秒（加载 15.07 秒、生成 23 token 用时 5.57 秒），结束后模型已卸载；这**不是**同时运行 Doris/数据库时的性能证明。16 GB 内存、4 GB 显存下，生成延迟与并行服务上限还须做完整链路实测；不能把检索查询同步绑在冷启动上。已存在的模型文件当前在 C 盘，本阶段不重新下载或擅自迁移；新增缓存和临时文件必须在 D 盘。
- 向量化使用 FastEmbed 支持的 `BAAI/bge-small-zh-v1.5` 中文模型（512 维，模型约 90 MB），只下载到 D 盘缓存，记录模型版本与索引版本。它是一个小型检索模型，不另启推理服务。请求期不允许偷偷下载模型；不可用时明确标记“仅关键词检索”，不伪称混合检索。
- 模型适配器支持 `off`、`openai_compatible`、`ollama` 三种显式配置。默认 `off`，知识库与确定性证据摘要照常可用，绝不暗中发起付费调用。远程演示优先考虑阿里云百炼北京地域的 `qwen-plus`：官方支持 OpenAI 兼容接口与工具调用，中文场景比较直接；DeepSeek 也是可选兼容服务，但模型名、价格与工具行为须在接入时按官方文档复核。代码不绑定单一供应商；请求前必须由用户在官方平台开通、设置消费限额并将密钥放入本机未跟踪环境变量，不在网页输入密钥，也不提交到 Git。
- 远程模式只发送本次用户问题、经权限过滤的最多五段短证据、聚合指标和有限会话摘要；不发送原始 PDF、整库资料、用户级行为明细、凭据或隐藏思维链。远程请求需有模型调用/工具调用/token 上限、硬截止时间、单次估算成本与审计记录。用户可明确切换到本地 Ollama；远程失败不自动启动 5.2 GB 本地模型，直接退到确定性证据摘要，避免 16 GB 本机突发卡顿。模型提供商变化不改变检索、授权和指标口径。
- 无模型或模型失败时，先返回独立知识检索结果；对界面内五类服务端登记的电商问题模板（订单/支付、配送/评价、排行、行为漏斗、口径/质量）可按模板 ID 和原问题匹配结果确定性调用对应已发布指标并展示证据卡。用户编辑模板问题后清除模板 ID；自由问题意图不明确时不猜指标类型，不把规则路径称作模型 Agent 成功。
- 本地 Ollama 由宿主机 FastAPI 通过 loopback 调用；不为了让容器访问它而默认开放 `0.0.0.0:11434`。容器化 API 到宿主模型的连通性是独立动态验收项，未测前不能声称 Compose 全链路可用。演示时按需运行 Doris、应用库、API 和选定模型，不常驻 Kafka/Flink/Trino 全栈。
- LangChain 仅负责单 Agent 的模型/工具编排与结构化输出，数据库事务、权限过滤、指标取数、超时与审计仍由现有后端代码负责。分别用假模型验证工具循环，再动态验证远程或本地真实模型；若模型超时或内存不足，保留快速检索和确定性证据摘要，不能假装模型已执行。是否改用更小本地模型须以实测质量/速度决定，不能自动下载到 C 盘。

## 3. 知识库生命周期

管理员可上传 Markdown、TXT、带文本层的 PDF，或导入仓库内受控的两份指标定义；不自动吞入所有旧文档，先人工筛掉过期口径。单文件上限 10 MiB、PDF 200 页；扫描件、加密 PDF、无法抽取文本或不支持的格式明确拒绝。原文件和抽取文本存入应用库，解析临时目录在 D 盘，不增加另一套文件服务。保存文档标题、分类、来源类型、来源链接/仓库路径、使用说明、SHA-256、版本、可见角色、上传者和时间。真实来源与项目自行整理的规则分开标注。上传后可预览原文与分块位置，不把原始文件送到外部模型服务。

同一文档允许草稿版本和一个已发布版本。先完整解析、分块、生成向量并校验块数/维度，再以事务切换发布指针；失败时原版本仍可检索。取消发布或删除立即从检索候选中消失，删除要覆盖原文、块和向量。引用包含文档 ID、版本、章节/页码、块 ID 与内容摘要；失效引用显示“来源已撤回”，不再提供旧正文。引用该文档的保存报告需失效或删除，不能通过报告绕过删除。

角色为现有 `admin`、`analyst`、`viewer`。仅管理员管理文档；检索和预览由后端按文档可见角色过滤，过滤发生在关键词与向量候选生成之前。报告默认仅创建者和管理员可读，不做跨用户共享。客户端隐藏按钮不是权限控制。所有写操作沿用会话和 CSRF；文件类型、大小和来源字段在服务端验证。

## 4. 检索与回答质量

- 解析时保留标题层级、段落、表格文字及 PDF 页码；按章节/段落分块，并限制在向量模型可处理的长度内，避免把一整份文档截断。对 `behavior-v1`/`orders-v1` 的 JSON 按指标项分块，引用仍指向原始定义文件和版本。内容重复块用 SHA-256 去重，不删除不同版本的可追溯身份。
- 关键词路对中文使用可解释的字符二元组、对英文/编号保留完整技术词，存储可索引词元；不把 PostgreSQL 默认英文全文检索称为“中文 BM25”。向量路用 pgvector 余弦距离。首批数千块先做精确 Top K，避免未经测量就引入 HNSW 的召回/内存取舍；若实测检索延迟达不到目标，再比较索引方案。
- 两路分别取候选，按倒数排名融合（RRF）并限制单文档重复块，返回最多五条正文片段、定位信息和来源状态。只检索已发布且当前角色可见的版本。无命中或证据不足时明确拒答；拒答阈值用独立标注集校准，不能靠模型自报“有把握”。检索结果作为不可信数据，不能指示模型更改工具、权限或系统规则。
- 选定生成模型只接收后端已筛选的短证据和只读指标结果。模型可在白名单中选择工具并组织语言，不能自行发 SQL、添加工具或填补缺失数值。结构化回答的每条观点必须引用本次证据 ID；模型自由文本不得直接承载数字、日期、百分比或跨源换算，同一条观点不合并 Olist 与 REES46 的证据，精确数值和时间窗口由后端从已发布指标生成证据卡。缺失/非法引用、越界数值、超时或模型不可用时降级为可追溯的摘录/指标卡，不能用编造的自然语言补位。
- 沿用第 10 章白名单、总 deadline、审计和失败封闭的安全规则，但原执行器只识别旧工具 ID，G4 不直接拿它执行新工具，也不把旧的模拟实时工具结果当作真实业务证据。新增只读工具包装仅调用既有 Olist/REES46 已发布指标服务，返回 `dataset_id`、`metric_run_id`、口径版本、窗口和发布时间。不同来源只能并列说明，不合并用户漏斗。报告保存问题、回答、证据 ID、run ID、生成时间和使用的模型/检索版本，不保存口令或隐藏思维链；旧 run 被新发布替换后，报告标明历史快照，不静默换成新指标。

## 5. 代码化单 Agent

`POST /api/v1/agent/ask` 先校验会话、分析员角色、CSRF、问题长度和请求预算，再为该用户构造单 Agent。LangChain `create_agent` 绑定显式选定的 `ChatOpenAI`（兼容 API）或 `ChatOllama`，以及三个后端包装的只读工具：`search_knowledge`、`get_published_behavior_metrics`、`get_published_order_metrics`。工具参数用明确的 Pydantic 枚举/范围验证；用户身份由服务端闭包传入，不由模型提供。知识工具始终执行已发布版本与角色过滤，指标工具只走既有服务方法，不提供任意 SQL、文件系统、网络或写入工具。

Agent 只允许有限模型调用和工具调用，并受一次请求的硬截止时间控制；LangChain 的限次中间件是第一层，G4 后端工具包装的预算与异常封闭是第二层。流程为“判断需要哪些证据 -> 调用工具 -> 读取受限观察结果 -> 输出结构化答案 -> 后端核对引用/数值”。每次调用记录工具名、状态、耗时和证据 ID，界面可展示步骤，但不公开模型隐藏思维链。限次、超时、空证据或不可信文档诱导额外工具调用均必须失败封闭。

只保存创建者可见的有限会话上下文，首版最多保留最近三轮问题/回答及证据 ID，不把整份文档或旧工具结果无限塞回模型。报告保存只接收本次服务端产生、属于当前用户的回答 ID，不信任浏览器提交的答案和证据。知识库检索 API 独立于 Agent，先返回可点击的检索结果；用户发起“AI 分析”时才按需调用显式选定的模型。这样慢速或不可用的模型不会拖慢知识库的基本功能。

优先支持能形成完整分析链的五类问题：订单趋势/支付结构、配送时效与差评、商品/品类排行、行为漏斗与商品兴趣、指标口径与数据质量。回答必须展示数据源、窗口、口径版本、run ID、限制和跳转到对应可视化页的入口。无订单级身份映射时不回答“REES46 浏览最终促成了多少 Olist 订单”；无实验或因果识别时不把趋势变化解释为因果。报告中的“建议”只作为可追溯的业务假设，不伪称模型发现了真实根因。

## 6. 页面与可观测性

工作台新增“知识库”和“AI 指标分析”两页，沿用 G3 的绿色体系但按内容设计交互，不复制六个图表页的模板。知识库页提供分类/来源/版本/权限状态、上传与发布、原文预览、检索结果和命中片段定位；AI 页区分问题、Agent 工具调用步骤、检索到的文档、指标工具证据、答案和报告，引用可点击回到具体块。加载、无答案、权限不足、索引失败、模型降级都有明确状态，不展示假数据。

记录导入块数、索引版本、检索耗时、候选数、模型耗时、降级原因和匿名化审计 ID，不记录用户口令、完整私人文档或模型内部思考。查询历史和报告只对有权用户开放。

## 7. 验收与实施顺序

1. **知识管理**：应用库扩展/迁移兼容检查；真实项目资料导入、预览、分块、版本、发布、删除与角色过滤；单测和一次真实 PostgreSQL 生命周期验证。旧认证链路必须保持通过。
2. **检索**：固定中文向量模型下载到 D 盘；关键词、向量、融合三条可比较的检索路径；用真实文档验证跨版本、中文口径词、英文技术词、无答案和越权；记录延迟及资源占用。
3. **有据 Agent 与页面**：编写 LangChain 单 Agent、三个只读工具包装、限次/截止时间、短会话状态、调用轨迹和证据校验；接入显式选择的兼容 API 或按需 Ollama、两页交互和报告。用假模型测试工具选取/越权/注入/超时，并用至少一种经用户开通的真实模型和真实已发布指标跑通一条完整调用链；未取得 API 密钥或本机资源不满足时，记录缺项而不伪称 Agent 动态验收通过。容器内 Ollama 访问未通过前，仅声明宿主机 API 的动态结果。
4. **独立评测**：至少 50 条人工标注且不用于反复调参的问题，覆盖知识、指标、混合分析、无答案、旧版本、越权、工具选择和提示注入。对比关键词/向量/融合的 Recall@5、引用正确率、拒答、Agent 工具选择/任务成功率、P95 检索耗时和本地模型耗时/内存。目标是融合 Recall@5 不低于最佳单路、引用 ID 100% 可定位、越权/撤回泄漏为零、当前规模的检索 P95 不超过 2 秒；不达标则如实记录并修正，不能预填“通过”。生成时间单独记录，不混进检索延迟。

所有演示结论只基于真实导入文档、真实已发布指标和实测结果；测试夹具仅用于安全边界。G4 不声称百万级文档索引或生产 SLA。现有 Olist/REES46 指标的真实性与局限继续沿用 G2/G3 证据；REES46 当前 1,002 条发布只能做正确性展示，正式跨月行为分析和对应 Agent 评测须等待 G5-A 的 2,199,938 条 run 通过后进行。

### 7.1 G4-A 检索基线（2026-10-09，未全部达标）

仅在隔离 PostgreSQL 16/pgvector 验证卷中导入 5 份白名单项目资料、共 243 块；没有切换正式应用库，也没有启动 Kafka/Flink/Doris 全栈。评测题为 10 条开发题（8 正例、2 无答案）和 30 条固定保留题（24 正例、2 无答案、4 条越权/撤回/旧版安全题）；安全题使用显式测试夹具，不充作真实业务数据。题目和目标定位见 `tests/fixtures/g4_knowledge_questions.json`，机器可读报告保存在本机 D 盘 `D:\EcommerceDev\temp\g4\knowledge-evaluation.json`，未提交原文和凭据。

| 固定保留题（Recall@5 分母 24） | 关键词 | 向量 | RRF 融合 |
| --- | ---: | ---: | ---: |
| 命中数 / Recall@5 | 21 / 87.50% | 18 / 75.00% | 20 / 83.33% |
| 检索 P95（30 次请求，含向量化时按该路计） | 41.665 ms | 45.258 ms | 51.759 ms |
