# G4 知识库与有据 AI 分析设计

日期：2026-10-08。状态：待用户审阅；这是 G4 的设计，不代表功能已实现。

## 1. 目标与边界

面向毕设答辩和数据开发/AI Agent 面试，交付能管理真实项目资料、检索正确版本、给出可定位引用，并结合已发布指标回答问题的系统。知识库是核心业务模块，不是聊天窗口里的预置答案。验收既看可用功能，也看检索评测、越权防护和本机资源测量。

沿用 G3 的 React 工作台、FastAPI、会话鉴权和 PostgreSQL 应用库；百万级行为流水仍归 Iceberg/Doris，不逐条向量化。知识库只保存数据字典、`behavior-v1`/`orders-v1` 口径定义、运行手册和有来源的排障记录。项目自行编写的资料明确标为“项目文档”，不冒充企业内部资料。Olist 与 REES46 是独立来源，不做跨源用户关联或虚构因果结论。

不新增 Milvus、Elasticsearch、LangChain、多 Agent、知识图谱、OCR 或常驻本地模型集群。不能因为本机装了模型就跳过检索、引用或评测。

## 2. 组件与运行方式

`真实文档/版本化指标定义 -> 解析与分块 -> PostgreSQL 文档/块/版本 + pgvector 向量 -> 权限过滤后的关键词/向量检索 -> 引用证据`

`用户问题 -> 检索证据 + 白名单指标工具 -> 后端校验 -> 可选 Ollama 生成 -> 带文档引用和指标 run ID 的回答/报告`

- 应用库使用 PostgreSQL 16 + pgvector，知识表放在独立 `knowledge` schema；原认证表与 Hive Metastore 不改。现有普通 `postgres:16.4-alpine` 镜像**没有经过扩展验收**。启用前检查实际卷和备份；若已有持久数据，不直接用不同基础镜像重挂旧卷，而是先隔离验证迁移。Schema 通过可重复执行的迁移创建，不能只依赖首次初始化脚本。
- 本机已安装 `qwen3:latest`，实测元数据显示 8.2B、Q4_K_M、约 5.2 GB，能力为生成/工具/思考，未列出 embedding。它仅按需生成自然语言，不承担向量化。16 GB 内存、4 GB 显存下，生成延迟与并行服务上限必须实测；不可把本地模型可启动等同于可流畅答辩。已存在的模型文件当前在 C 盘，本阶段不重新下载或擅自迁移；新增缓存和临时文件必须在 D 盘。
- 向量化使用 FastEmbed 支持的 `BAAI/bge-small-zh-v1.5` 中文模型（512 维，模型约 90 MB），只下载到 D 盘缓存，记录模型版本与索引版本。它是一个小型检索模型，不另启推理服务。请求期不允许偷偷下载模型；不可用时明确标记“仅关键词检索”，不伪称混合检索。
- 本地 Ollama 首版由宿主机 FastAPI 通过 loopback 调用；不为了让容器访问它而默认开放 `0.0.0.0:11434`。容器化 API 到宿主模型的连通性是独立动态验收项，未测前不能声称 Compose 全链路可用。演示时按需运行 Doris、应用库、API 和 Ollama，不常驻 Kafka/Flink/Trino 全栈。

## 3. 知识库生命周期

管理员可上传 Markdown、TXT、带文本层的 PDF，或导入仓库内受控的两份指标定义；不自动吞入所有旧文档，先人工筛掉过期口径。单文件上限 10 MiB、PDF 200 页；扫描件、加密 PDF、无法抽取文本或不支持的格式明确拒绝。原文件和抽取文本存入应用库，解析临时目录在 D 盘，不增加另一套文件服务。保存文档标题、分类、来源类型、来源链接/仓库路径、使用说明、SHA-256、版本、可见角色、上传者和时间。真实来源与项目自行整理的规则分开标注。上传后可预览原文与分块位置，不把原始文件送到外部模型服务。

同一文档允许草稿版本和一个已发布版本。先完整解析、分块、生成向量并校验块数/维度，再以事务切换发布指针；失败时原版本仍可检索。取消发布或删除立即从检索候选中消失，删除要覆盖原文、块和向量。引用包含文档 ID、版本、章节/页码、块 ID 与内容摘要；失效引用显示“来源已撤回”，不再提供旧正文。引用该文档的保存报告需失效或删除，不能通过报告绕过删除。

角色为现有 `admin`、`analyst`、`viewer`。仅管理员管理文档；检索和预览由后端按文档可见角色过滤，过滤发生在关键词与向量候选生成之前。报告默认仅创建者和管理员可读，不做跨用户共享。客户端隐藏按钮不是权限控制。所有写操作沿用会话和 CSRF；文件类型、大小和来源字段在服务端验证。

## 4. 检索与回答质量

- 解析时保留标题层级、段落、表格文字及 PDF 页码；按章节/段落分块，并限制在向量模型可处理的长度内，避免把一整份文档截断。对 `behavior-v1`/`orders-v1` 的 JSON 按指标项分块，引用仍指向原始定义文件和版本。内容重复块用 SHA-256 去重，不删除不同版本的可追溯身份。
- 关键词路对中文使用可解释的字符二元组、对英文/编号保留完整技术词，存储可索引词元；不把 PostgreSQL 默认英文全文检索称为“中文 BM25”。向量路用 pgvector 余弦距离。首批数千块先做精确 Top K，避免未经测量就引入 HNSW 的召回/内存取舍；若实测检索延迟达不到目标，再比较索引方案。
- 两路分别取候选，按倒数排名融合（RRF）并限制单文档重复块，返回最多五条正文片段、定位信息和来源状态。只检索已发布且当前角色可见的版本。无命中或证据不足时明确拒答；拒答阈值用独立标注集校准，不能靠模型自报“有把握”。检索结果作为不可信数据，不能指示模型更改工具、权限或系统规则。
- `qwen3:latest` 只接收后端已筛选的短证据和只读指标结果。模型可组织语言，不能自行发 SQL、选择任意工具或填补缺失数值。后端验证其结构化输出的引用 ID 必须来自本次证据集，数值和时间窗口必须来自已发布指标；无效输出、超时或 Ollama 不可用时降级为可追溯的摘录/指标卡，不能用编造的自然语言补位。
- 复用第 10 章的工具白名单、总 deadline、审计和失败封闭边界，但不把旧的模拟实时工具结果当作 G4 真实业务证据。新增只读工具只调用既有 Olist/REES46 已发布指标契约，返回 `dataset_id`、`metric_run_id`、口径版本、窗口和发布时间。不同来源只能并列说明，不合并用户漏斗。报告保存问题、回答、证据 ID、run ID、生成时间和使用的模型/检索版本，不保存口令或隐藏思维链；旧 run 被新发布替换后，报告标明历史快照，不静默换成新指标。

## 5. 页面与可观测性

工作台新增“知识库”和“AI 指标分析”两页，沿用 G3 的绿色体系但按内容设计交互，不复制六个图表页的模板。知识库页提供分类/来源/版本/权限状态、上传与发布、原文预览、检索结果和命中片段定位；AI 页区分问题、检索到的文档、指标工具证据、答案和报告，引用可点击回到具体块。加载、无答案、权限不足、索引失败、模型降级都有明确状态，不展示假数据。

记录导入块数、索引版本、检索耗时、候选数、模型耗时、降级原因和匿名化审计 ID，不记录用户口令、完整私人文档或模型内部思考。查询历史和报告只对有权用户开放。

## 6. 验收与实施顺序

1. **知识管理**：应用库扩展/迁移兼容检查；真实项目资料导入、预览、分块、版本、发布、删除与角色过滤；单测和一次真实 PostgreSQL 生命周期验证。旧认证链路必须保持通过。
2. **检索**：固定中文向量模型下载到 D 盘；关键词、向量、融合三条可比较的检索路径；用真实文档验证跨版本、中文口径词、英文技术词、无答案和越权；记录延迟及资源占用。
3. **有据 Agent 与页面**：接入现有已发布指标工具与按需 Ollama，做引用/数值校验、模型故障降级、两页交互和报告；在本机分别验证无模型和有模型模式。容器内 Ollama 访问未通过前，仅声明宿主机 API 的动态结果。
4. **独立评测**：至少 50 条人工标注且不用于反复调参的问题，覆盖知识、指标、混合分析、无答案、旧版本、越权和提示注入。对比关键词/向量/融合的 Recall@5、引用正确率、拒答、任务成功率、P95 检索耗时和本地模型耗时/内存。目标是融合 Recall@5 不低于最佳单路、引用 ID 100% 可定位、越权/撤回泄漏为零、当前规模的检索 P95 不超过 2 秒；不达标则如实记录并修正，不能预填“通过”。生成时间单独记录，不混进检索延迟。

所有演示结论只基于真实导入文档、真实已发布指标和实测结果；测试夹具仅用于安全边界。G4 不声称百万级文档索引或生产 SLA。现有 Olist/REES46 指标的真实性与局限继续沿用 G2/G3 证据。
